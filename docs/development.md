# Development

[Back to README](../README.md)

## Prerequisites

Use **Node.js 24.x** and npm. The `engines` field also accepts Node.js 22.12+ within the 22.x series. Install dependencies using the committed lockfile:

```sh
npm ci
npm run dev
```

The development server binds to all network interfaces. Use the printed localhost address for local work. An HTTP address on your LAN is not sufficient to test secure-context capabilities such as persistent folder access or production PWA behavior.

No environment variables or backend services are needed. The optional `PLAYWRIGHT_CHANNEL` setting selects a browser for browser tests and screenshot generation.

## Commands

| Command                    | Purpose                                                                |
| -------------------------- | ---------------------------------------------------------------------- |
| `npm ci`                   | Install locked dependencies and prepare PDF.js resources               |
| `npm run dev`              | Start the Vite development server                                      |
| `npm run build`            | Check application types, build `dist/`, and generate the offline cache |
| `npm run preview`          | Serve the production build, normally on port 4173                      |
| `npm test`                 | Run the Vitest unit suite                                              |
| `npm run lint`             | Lint application and test TypeScript with ESLint                       |
| `npm run format`           | Format the paths listed in the script with Prettier                    |
| `npm run test:e2e`         | Run Playwright desktop and mobile flows                                |
| `npm run docs:screenshots` | Capture the documentation images from a production build               |

Prettier uses two-space indentation, single quotes, trailing commas, and a 100-character line width. To check formatting without writing files:

```sh
npx prettier --check src tests scripts docs README.md CONTRIBUTING.md AGENTS.md *.ts *.json
```

## Test setup

Unit tests run without a browser. `fake-indexeddb` provides IndexedDB in tests that exercise folder snapshots and progress.

For browser tests, build first and install Chromium:

```sh
npm run build
npx playwright install chromium
npm run test:e2e
```

Playwright starts the preview server on port 4173. If it cannot start, check whether that port is already in use. On a supported Linux system, missing browser libraries can be installed with `npx playwright install --with-deps chromium`.

To use an existing Chrome installation on a POSIX shell:

```sh
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e
```

The suite covers file selection, offline reopening, folder hierarchies, literal search, multiple linked folders, manual refresh, permission recovery, safe unlinking, reader text search, file navigation, touch swipes and native panning, independent split panes, focus mode, previews, and sidebar visibility. Browser fixtures are generated with `pdf-lib`; no private scores are used.

The mobile project emulates a Pixel 7 in Chromium. Persistent folder selection, installation, and cloud-backed providers still need validation on the target physical device.

## Documentation screenshots

The screenshot script generates original demonstration notation in memory, opens it through the actual file picker flow, and saves three images under `docs/images/`. It does not capture local music folders or store the generated PDF files.

```sh
npm run build
npx playwright install chromium
npm run docs:screenshots
```

Or, with Chrome installed:

```sh
PLAYWRIGHT_CHANNEL=chrome npm run docs:screenshots
```

The script starts its own preview server on port 4175 and closes the browser and server afterward. The screenshots are part of the documentation and should be updated after meaningful visual changes.

## Generated and local files

Do not commit `node_modules/`, `dist/`, browser test reports, `.vercel/`, local assistant configuration, `.aws/`, or `.env` files. `public/pdfjs/` is generated by dependency installation and is ignored; app icons and documentation screenshots are intentional repository assets.

Keep the manifest and lockfile together when changing dependencies. See [Contributing](../CONTRIBUTING.md) for review expectations.
